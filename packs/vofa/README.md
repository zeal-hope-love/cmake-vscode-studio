# vofa 模块包

**VOFA+ 在线调参**：把工程里挑出来的变量周期发到 VOFA+ 画波形，并支持用文本命令在线改参数。
调 PID 不用改代码、不用重烧。波特率和 RX DMA 由工具直接写进 .ioc 并跑一遍 CubeMX。

## 装了之后工程里多了什么

```
application/vofa/
  vofa_task.c      模块本体（通用，不要手改）
  vofa_task.h      对外接口（不要手改）
  vofa_types.h     fp32/bool_t 来源适配（不要手改）
  vofa_config.h    ← 工具生成：串口 / 频率 / 开关
  vofa_bind.c      ← 工具生成：调哪些变量（就是你在界面上勾的那些）
```

**分工**：模块本体一次装好就不动了。以后想换调参目标，只重新生成 `vofa_bind.c` 一个文件 ——
`CMakeLists.txt`、`freertos.c`、`vofa_task.c` 都不用再碰。

## 怎么用

1. VOFA+ 打开串口，协议选 **JustFloat**
2. 发 `list` 看有哪些可调参数，`get 名字` 读，`set 名字 值` 改（立即生效）
3. 波形通道就是 `vofa_bind.c` 里注册的顺序，对应 VOFA+ 的 ch0、ch1…

> 在线改的值**不落盘**，断电就回到源码里的初值。调好记得写回源码。

## 两种「看什么」的方式

| | 注册表（`vofa_bind.c`） | 地址表（不改源码） |
|---|---|---|
| 怎么配 | 界面上勾变量 → 生成代码 → 编进固件 | 界面上勾变量 → 生成一串 `am` 命令 → 发一次 |
| 换变量 | 重新生成 + 重新编译 + 重新烧录 | 只在上位机重选，源码不动 |
| static 变量 | 取不到 | **能**（符号表里有地址） |
| 结构体成员 `x->y` | **能**（代码里取地址） | 不能（成员没有独立符号） |

地址表命令（工具里生成，一条线发完）：

```
ac;am 0 0x20001A3C i16;am 1 0x2000A7B0 f
```

- `ac` 清空所有槽，`am <槽号> <地址> <类型>` 配一路（最多 16 路），`al` 列出已配的
- 帧里 **地址槽排在注册通道前面**，所以地址槽的第一个就是 VOFA+ 的 ch0
- 类型：`f` `u8` `i8` `u16` `i16` `u32` `i32`
- 单点读写：`rd 0x20001A3C i16`、`wr 0x20001A3C i16 1.5`

勾了哪些变量存在 **`application/vofa/vofa_addr.json`**：跟工程走，可提交 git，
关掉工具、换台机器打开都还在。它和 `vofa_map.json` 是两份文件 ——
那份给生成器看（编译期生效），这份只记「运行时按地址看什么」，
改它不需要重新生成、也不需要重新编译。

⚠️ 地址来自编译出来的 `.elf`。**改了代码重新烧录后，要在工具里点一次「重新读取」**，
否则读到的是别的变量，而且不会报错。越界地址会被固件挡掉（`VOFA_MEM_CHECK`，
上界取链接脚本的 `_estack`），关掉它就可能 HardFault。

## 关于串口

- **TX（波形上行）**：用工程里现成的「一次性 DMA 发送」函数（`usart1_tx_dma_enable` 这类）
- **RX（命令下行）**：默认走**逐字节中断**，只需要串口全局中断

**中断入口**：`VOFA_USE_BUILTIN_IRQ=1` 时模块在运行时自己开 NVIC，并自带
`USART1_IRQHandler`（弱符号；工程里没有它，不会重复定义）。工程自己已经有中断入口
（比如 `remote_control.c` 里的 `USART3_IRQHandler`），把这个开关关掉，模块就不插手。

### 关于波特率和 RX DMA

模块运行时改不了这两样——**它们写在 `Src/usart.c` / `Src/dma.c` 里，由 CubeMX 生成**。
所以工具的做法是：直接改 `.ioc`，再把 CubeMX 跑一遍。

| 参数 | 工具做了什么 |
|---|---|
| 波特率 | 写 `USARTx.BaudRate` 并补进 `IPParameters` → CubeMX 重新生成 `Src/usart.c` |
| 接收方式 = dma | 按芯片型号查表加 `USARTx_RX` 的 DMA 请求（Stream/Channel 是硬件连线决定的），连带使能该 Stream 中断并让 CubeMX 生成中断函数 |
| RX DMA 模式 = 循环 / 单次 | 写 `Dma.<串口>_RX.<槽>.Mode`（`DMA_CIRCULAR` / `DMA_NORMAL`），同时改 `vofa_config.h` 里的 `VOFA_RX_DMA_CIRCULAR` |
| 写完后让 CubeMX 重新生成 | 关掉的话只改 `.ioc`，代码要你自己去 CubeMX 点一次 Generate Code |

**这两种 DMA 模式都在固件里支持**，区别只在「谁来接上下一帧」：

- **循环（默认）**：DMA 地址指针自己回卷，空闲中断里按「上次偏移 → 本次偏移」取增量。
  两次命令之间没有空窗，921600 也不会丢字节。
- **单次**：一块 128 字节缓冲收满（或某些 HAL 版本在空闲事件里就把 DMA 关掉）之后，
  DMA 不再自动继续。固件在 `HAL_UARTEx_RxEventCallback` 里重新挂一帧。
  重挂要几个微秒，正好卡在下一帧开头时可能丢字节 —— 所以默认不选它。

⚠️ `.ioc` 里的模式和 `VOFA_RX_DMA_CIRCULAR` **必须一致**。对不上就是「第一条命令
能收到、之后全没反应」：`.ioc` 写单次而固件以为在循环，就永远没人重挂；
`.ioc` 写循环而固件以为在单次，就会在缓冲绕回时把指针重置、把半帧当垃圾丢掉。
工具改 `.ioc` 时会把这两处一起改，不用你手动对。

工程里本来就有 `USARTx_RX` 的 DMA 时，工具**只改 `Mode` 一个字段**，
Stream、Channel、优先级一律原样保留 —— 那些是硬件连线和你的取舍，不该被覆盖。
如果当前就是目标模式，一个字节都不改（不会为了无关改动白跑一次 CubeMX）。

写之前会存快照，`Src/` 和 `Inc/` 一起存——CubeMX 生成坏了能整体还原。

⚠️ 两件必须知道的事：

1. **`.ioc` 改了但代码没重新生成 = 没改**。上位机能连上、波形也在发，但收发全是乱码，
   而且不会有任何报错。所以写完工具会回读 `Src/usart.c` 里的 `huartX.Init.BaudRate`
   核对一遍，对不上会直接说。
2. **CubeMX 会用它自己的换行符重写 `Src/` 和 `Inc/`**。你的文件原来是 LF 的话，
   git 里看起来是「整个文件都改了」，实际内容只有需要的几行不同。

`.ioc` 里没有 `USARTx.VirtualMode` 说明这个串口在 CubeMX 里还没启用（引脚没分配），
这种情况工具会直接拒绝改，让你先去 CubeMX 把它开成 Asynchronous。

## 依赖

| 需要 | 说明 |
| --- | --- |
| FreeRTOS / CMSIS-OS | 用 `osThreadCreate` 起任务 |
| 一个空闲串口 | 别和 DBUS（通常 USART3）、裁判系统（通常 USART6）冲突 |
| `struct_typedef.h` | 可选。没有的话模块自己用 `<stdint.h>`/`<stdbool.h>` 定义 fp32/bool_t |

## 常见问题

**收了命令没反应？** 先确认 `VOFA_USE_BUILTIN_IRQ` 是否为 1（或者 CubeMX 里勾了串口中断），
再用 `list` 看有没有回显 —— 有回显说明链路通了。

**波形卡顿/丢数据？** 通道太多 × 频率太高把带宽吃满了。调低 `VOFA_SEND_HZ`，
或减少监看通道。蓝牙透传空中吞吐只有几 KB/s。

**`set` 之后波形没变？** 检查这个参数是不是真的被注册成了**可调参数**（`get` 能读到就说明注册了）。
