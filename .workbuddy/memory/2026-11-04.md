## ✅ 真正的根因（推翻了上面「继承 agent 沙箱」的结论）

**`C:\Users\PoXia\Desktop\DSH_Workspace` 目录被设成了低完整性级别（Low IL）**

```
DSH_Workspace  →  Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)   ← 异常
Desktop\RM     →  Mandatory Label\Medium Mandatory Level:(OI)(CI)(NW) ← 正常
```

Windows 的规则：**从低完整性文件启动的进程，自身也被降为低完整性**；低完整性进程
"禁止向上写"（deny write-up），因此写 Desktop / AppData 全部返回 ERROR_ACCESS_DENIED，
Node 把它映射成 `EPERM`。

### 关键实验（node.exe 复制到不同目录启动，查进程令牌完整性）
| 启动位置 | 进程 IL |
|---|---|
| `DSH_Workspace\CMakeVSCodeStudio\.tmp\` | LOW |
| `DSH_Workspace\` | LOW |
| `Desktop\RM\` | Medium |
| `%TEMP%` / `Desktop\` | Medium |

改名、改哈希、换父进程、停 CodexSandboxService **都无效** → 因为标签是从目录继承到文件上的。

- 读进程完整性：P/Invoke `OpenProcess` + `OpenProcessToken` + `GetTokenInformation(TokenIntegrityLevel=25)`，

- 读目录/文件标签：`icacls <path>`，看 `Mandatory Label\...`
- 注意：**`Get-Acl` 看不到完整性标签**，所以早先比对 ACL 一切"正常"，误导了排查方向

## 符号扫描：不再要求用户手写 extern（15:0x）

**用户抱怨**：「要把所有想调的量做成全局、并在头文件里 extern 声明，怎么这么麻烦」。

**拆解成三层，只有第 2 层该由工具解决**：
1. C 语言必然：`vofa_bind.c` 是独立编译单元，取地址必须看得见声明。
2. **工具缺陷（已修）**：扫描器 `parseInstances` 只匹配 `\bextern\s+` 开头，
   于是「在 .c 里定义、头文件没写 extern」的变量完全扫不到。但这类变量
   链接期是外部符号 —— **生成器在 vofa_bind.c 顶部自己补一行 extern 就行**，
   合法 C，不用动用户源码。
3. C 语言硬约束（无解）：`static` 变量链接期是 local symbol，
   别的编译单元永远拿不到地址。只做「列出来 + 说明原因」，不假装它不存在。

**实现**：
- `symbolScanner.ts` 新增 `parseTopLevelVars()`：花括号深度 0 处按 `;` 切语句，
  天然排除函数体/struct 体/初始化器。配 `blankPreprocessor()`（预处理行抹等长空格，
  偏移不变，否则 `#include` 会和下一条语句黏住）、`splitTopLevel()`（跳初始化器逗号）、
  `stripInitializer()`。
- `RawInstance` 加 `externDecl`（形如 `extern fp32 battery_voltage;`）与 `fileStatic`。
- `SymbolScanResult` 加 `statics: SymbolNode[]`；`SymbolNode`/`VofaBinding` 加 `externDecl`。
- `ChannelBinding`/`ParamBinding`/`PidBinding` 加 `externDecl`，一路传到 `renderBind`，
  填进模板新增的 `${EXTERN_DECLS}`（`packs/vofa/files/vofa_bind.c.tpl`）。
- 过滤噪音：`^(_|arm_|__)` 掐掉链接脚本符号（_estack/_end）和 CMSIS-DSP 常量表。
- 排序 `dirRank`：application > components > bsp > Src/Inc > 其他。
  不加的话字母序会把库符号排最前，看起来像没扫到。

**真机实测**（user 的 test-1103，146 个文件）：
可绑定根 223（原 134），其中 **89 个靠自动补声明才能绑**，
static 38 个单列。`yaw_ins_int_1000` / `gyro_offset` / `accel_offset` /
`battery_voltage` 都进来了；`INS_gyro` 是 static 故进 static 表。

## 结论：vofa 包不碰 .ioc、不跑 CubeMX

用户问「会修改 .ioc 并让 CubeMX 重新生成吗」—— 不会。实际写入范围：
