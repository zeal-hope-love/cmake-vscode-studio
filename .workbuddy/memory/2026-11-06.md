### 更新入口改到应用内 + 安装器自杀修复（用户反馈）
反馈原文两件事：① 顶部「有新版本」横幅的「查看更新」直接开浏览器，
希望跳到「关于与版本」页优先引导应用内下载；② 安装器点「自动关闭并继续」
把 CV Studio 关了，**把安装器自己也关了**。

**② 的根因（重要，别再踩）**：`installer/src/main.ts` 的 `ensureAppStopped()`
用的是 `taskkill /F /T /IM "CV Studio.exe"`。`/T` 会顺着进程树往下杀，
而安装器正是应用内更新时由 CV Studio `spawn(detached)` 拉起的**子进程**
（detached 只影响控制台，不改父子关系）→ 顺带把自己杀了，窗口凭空消失。

修法：改成 PowerShell `Get-CimInstance Win32_Process` 拿全量 PID，
同名进程**逐个** `taskkill /F /PID`（去掉 `/T`），并排除 `process.pid`。
Electron 的 renderer/GPU 进程映像名都一样，在列表里，所以不靠 `/T` 也清得干净。
**不要**顺手把祖先链排除 —— 父进程正是要关的那个。
另外 `isAppRunning()` 拆成两个：重量级 `appProcesses()`（要杀谁）+
轻量 `quickIsRunning()`（tasklist 轮询）。「我自己关」原来查一次就返回，
用户还没关完必然失败 → 改成最多轮询 20 秒。

**① 的做法**：store 加 `focusUpdate()`（置 `activePage='about'` + `updateFocusSeq++`），
`UpdateNotice` 加 `onOpenAbout` prop，横幅主按钮改成切页；AboutPage 监听序号，
`scrollIntoView('#update-card')` + `.card-flash` 闪一下（`--accent` 描边，1.6s 收）。
横幅右侧留了个 `↗` 仍可开浏览器（网络差时的退路）。完整卡片的 Card 加了 `id="update-card"`。

⚠️ 安装器改动**必须重新打包 setup.exe 才生效**（`CVSTUDIO_STAGING=... npm run dist:setup`），
应用内那个旧安装包还是自杀版。

## 字标对齐（第三次才对）：别按字体比例猜，去量墨迹

`cv` + 黑底 `STUDIO` 方框一直差 2~3px，前两次按「升部/降部 3:1」估算全错。

**正确做法**：无头 Chrome 里 canvas `measureText('cv')` 取 `actualBoundingBoxAscent/Descent`
（墨迹包围盒），配合 `fontBoundingBoxAscent` 反推基线在行盒里的位置：

    基线 = (行高 - 升部 - 降部) / 2 + 升部

Segoe 在 32px 下升降部是 **35 / 8**（和 43，不是 3:1）：
- `line-height: 1` → 基线 29.5px（半像素，黑框上沿被抗锯齿糊成灰）
- 改 **line-height: 33px** → 基线正好 30px 整
- 方框 `height: 16px`（= x-height）+ `align-items: flex-end` + `margin-bottom: 3px`
- 实测：方框 14.00–30.00，墨迹 13.50–30.00（那 0.5 是抗锯齿）

像素验证：4 倍 DPR 截图 → 按行统计「整行 85% 以上是黑」定方框边界，左边字母区统计暗像素行定墨迹。
别用 min/max 全图扫，会被页面下方其它文字干扰。

改安装器 CSS 只影响 setup.exe 外壳，**app.asar 不用重打、版本号也不用变**，
直接 `gh release upload v2.0.2 文件 --clobber` 覆盖同名资源即可。

## 删不掉的 asar：重启也治不好，但能「清零」

- 现象：`app.asar` / `default_app.asar` 报「另一个程序正在使用」，**重启后依旧**；
  独占打开也是 sharing violation；attrib 只有 A。新拷进去的 asar 却能正常删。
- 持有者查不到：进程列表里没有 electron（偶尔冒出 4 个 `node_modules/electron/dist/electron.exe`
  又自己退了）。怀疑是杀软过滤驱动（火绒 usysdiag / wsctrl11）或残留内核句柄，没实锤。
- **技巧**：这类文件能以写方式打开，只是没给 share-delete → `: > 文件` 截断成 0 字节，
  空间立刻回收，只剩空壳目录。这次把 274MB 残留压到 ~18MB（全是 0 字节文件 + 空目录）。
- **删目录的正确姿势**：`cmd //c "del /f /s /q .tmp\*"` 0.1 秒扫完；
  而 bash 里 `for f in $(find ...); do rm -f "$f"; done` 花了 **16 分钟**（每文件一次 AV 扫描）。

  trash 失败则 `FAIL_CLOSED`。所以大批量清理走 bash + cmd del，别用 PowerShell 的 Remove-Item。

## ⚠️ electron-builder 会覆盖源 package.json

`npx electron-builder --win portable` 这次把**源目录**的 `package.json` 写成了裁剪版
（只剩 name/version/main/dependencies），`scripts` 和 `devDependencies` 全丢。

## git push 与发版要用不同通道

- `git push` 走 schannel 会报 `CRYPT_E_NO_REVOCATION_CHECK` —— 本机代理（SteamTools）
  做了 TLS MITM，吊销检查拿不到 CRL。`schannelCheckRevoke=false` 和 `sslBackend=openssl`
  都不管用（后者报 unable to get local issuer certificate）。
- **可用组合**：把 Root 存储里的 SteamTools 证书导成 PEM，然后
  `git -c http.sslBackend=openssl -c http.sslCAInfo=".tmp/steamtools-ca.pem" push`。
  `.tmp/steamtools-ca.pem` 是临时文件，被清理后要重新导（步骤见 TROUBLESHOOTING 第六节）。
- `gh release create/upload` 不受影响（Go 的 TLS 栈读系统证书库），发版照常走 gh。

- 沙箱 preload 移除 `Buffer` / `setImmediate` / `require('events'|'timers'|'url')`
  → 本项目 `src/preload/index.ts` 一样都没用，而且窗口是 `sandbox: false`
- `chromeMediaSource: 'desktop'` 拒绝 webContents 源 → 没用到屏幕捕获
- `contentTracing.enableHeapProfiling` 移除 → 没用到
- `safeStorage` 三个同步 API 弃用（46 才删）→ 没用到

验证顺序（都过）：`typecheck` → `selftest` 386 项 → `build` → **真机启动** →
用 CDP 读 `/json/list` 确认 `title=CV Studio`、url 指向 `out/renderer/index.html`
（比截图可靠，截图要 Add-Type 被安全策略拦）。

## 打包必须输出到工作区外，否则一定 EBUSY

工作区里**任何新写出来的 asar 会立刻被句柄锁住**（监视/索引服务），于是
electron-builder 第二步 `unlink app.asar` 直接 `EBUSY`。表现：

```
⨯ EBUSY: resource busy or locked, open 'release-204\win-unpacked\CV Studio.exe'
⨯ EBUSY: resource busy or locked, unlink 'release-204\win-unpacked\resources\app.asar'
```

第一次是 exe（刚解压被杀软扫），第二次是 asar（被索引锁）——重试没用，换目录才行。

**能跑通的完整姿势**（2.0.4 就是这么打的）：

```bash
# 1. 应用本体打到工作区外
npx electron-builder --win --dir -c.directories.output=C:/Users/PoXia/AppData/Local/cvbuild/release-204
# 2. 安装器：暂存目录也在外面，unpacked 指向上一步
CVSTUDIO_UNPACKED="C:/.../cvbuild/release-204/win-unpacked" \
CVSTUDIO_STAGING="C:/.../cvbuild/stage-204" npm run dist:setup
# 3. 绿色版
npx electron-builder --win portable -c.directories.output=C:/.../cvbuild/portable-204
# 4. 只把成品 exe 复制回 release/，中间目录整个删掉（1.4 GB）
```

`%LOCALAPPDATA%\cvbuild` 不在监视范围，一次都没失败过。

## CI 一直红的三层原因（都修了）

`release` 流水线从 v1.3.4 起每次都是红的，其实叠了三个独立问题：

1. **`npm ci` 拒装**：lock 里 `browserslist` 记的是 `node-releases ^2.0.57`（锁 2.0.58），
   而包实际要求 `^2.0.63`。`npm install` 重新解析后解决。
2. **自检 4 项硬断言 OpenOCD**：runner 上没装，判成失败。新增 `skip()`，
   环境不具备时跳过并单独计数（输出 `·`，不计入 failures）。
3. **打包步骤炸在 publish**：electron-builder 在 CI + 有 tag 时自动 publish，
   拿不到 GH_TOKEN 就报错（包其实已经打出来了）。加 `--publish never`。

## 两个容易误删的东西

- `.vscode/`：被删过一次，里面是 F5 调试配置（"启动并调试（主进程）"）。
  `.gitignore` 明确写了"故意提交"，删了 `git checkout -- .vscode` 恢复。
- 根目录 4 个 `tsconfig*.json` 是分层配置（base / node / web / 入口），不是重复文件。
