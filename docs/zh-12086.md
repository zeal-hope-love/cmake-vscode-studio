本贴是 #12085 的延伸。#12085 只要求关闭那个可继承的 Low 标签；这一篇是更大的诉求：**Windows 沙箱的整个权限面都应该由用户配置——完整性级别、ACL 条目、以及每一条施加到哪儿——而不是一个没有任何旋钮的固定策略。**

## 为什么值得单独开一贴

我把 discussion 翻了一遍（约 1270 条）。**每一条 Windows 沙箱报告都是症状报告**：

- #9649 —— 可继承 Low 标签导致树内构建产物以 Low 完整性运行
- #11193 —— 给卷根打标，把该卷上每个 Chromium 应用都搞崩了
- #10676 —— 临时根 / MIC 失败
- #10951、#11214、#11312、#11536、#11696、#11760、#12025 … —— `0xC0000142` / `STATUS_DLL_INIT_FAILED` / 命名管道被拒 这一大族
- #11090 —— 要求*放宽*一个前置条件（属主检查）

另外三条算是"配置形态"的请求，方向相邻，但**都不是本篇要的东西**：

- #10882 —— **额外可写根目录**（改的是"可写范围"，不是"如何被约束"）
- #11720 —— **`backend: 'platform' | 'external'`**（整个委托给宿主）
- #10945 —— 把**授权**和**沙箱模式**分离

**没有人提过本篇提的东西**：一个一等的、由用户定义的描述——告诉 Windows ACL 后端该施加什么安全姿态。社区一直在为一个硬编码策略的*输出*打补丁，而**策略本身是不可寻址的**。

## 一句话概括问题

Windows 上的 `workspace-write` 是**一个固定的、带强烈倾向的策略**——

`[Low 完整性标签 (OI|CI)] + [Everyone 删除子项拒绝] + [S-1-4-* 能力 SID]`

——无条件施加到用户打开的任意文件夹上，永久，不可见，不可配置，也没有回收路径。

**这个捆绑包里没有任何一项是用户所选的*策略*真正要求的。** `workspace-write` 的含义是"agent 可以在工作区内写，别的都不行"。实现方选了一种特定机制来实现它，然后把**机制的副作用变成了不可谈判的**。

## 用户应该能定义什么

### 1. 完整性级别

现在只有一个选项："Low、继承、到处"。用户应该能表达：

- **level** —— `untrusted` / `low` / `medium`（默认 `low`）
- **target** —— `token`（agent 的进程）和/或 `tree`（文件）——这两者现在被焊死在一起，而只有 token 那个是承重的
- **inheritance** —— `none` / `OI` / `CI` / `OI|CI`（现在永远 `OI|CI`）
- **no-write-up** —— 是否保留 `SYSTEM_MANDATORY_LABEL_NO_WRITE_UP`
- **where** —— 工作区根，还是 DSH 自管的临时子树（我的偏好：只打临时目录，用户的树保持环境原生的完整性级别）

关键洞察，再强调一遍因为它是核心：**`integrity: { token: low }` 和 `integrity: { tree: low }` 应该是两个独立设置。** 前者约束 agent——那是安全属性；后者把用户编译器产出的每一个可执行文件降级——那是代价。而现在这两者在体验上无法区分。

### 2. ACL 条目

那三条常驻条目应该每一条都能单独寻址：

- **`S-1-4-*` 能力 SID** —— 保留（agent 的写授权）/ 去掉
- **`Everyone` DENY** —— 现在是 `(CI)(DC)`，即带容器继承地拒绝 `FILE_DELETE_CHILD`。**这就是搞坏回收站和 `electron-builder` 清理的那条。** 用户应该能限定它的作用域（只在 DSH 自己创建的目录上）、收窄它、或者去掉它——并且在动手之前知道它到底保护了什么。
- **每条的继承标志** —— `OI` / `CI` / 两者 / 都不要

还有一点至关重要：

- **一个明确的"将要写入什么"预览。** 施加之前，把将要添加的确切 SDDL 显示出来。现在是用户在事后，从论坛帖子里读 `icacls` 输出才知道发生了什么。

### 3. 作用域与生命周期

- **哪些路径**获得这些条目（工作区根、DSH 临时目录、显式额外路径）
- **排除项** —— `*.exe` / `*.dll` / `*.node` / 用户指定的 glob。给可执行文件打标本来就是净负的（见下），所以这**本来就该是默认值**，而不是选项。
- **`standing` 还是会话级** —— 现在常驻授权是"intended end state, nothing to revoke"（`sandbox-local/src/index.ts:406-416`、`grant.ts:116-140`）。这应该是一个选择；而无论怎么选，`dsh sandbox release` 都必须存在。
- **拒绝卷根 / 驱动器根** —— 在写入任何东西之前（#11193）

### 4. 内省能力

- `dsh sandbox status --workspace <dir>` → 当前标签、SID、拒绝条目、继承标志，以及**哪些是 DSH 写的、哪些是原本就有的**
- `dsh sandbox release --workspace <dir>` → 精确移除那些

`Get-Acl` 根本不显示强制标签；`icacls` 是唯一能看到它的方式，而没有任何东西提示用户去看。**如果 DSH 敢往用户文件系统写安全描述符，它就该能报告并移除它。**

## 草图

```yaml
- id: sandbox
  config:
    windowsAcl:
      integrity:
        token: { level: low, noWriteUp: true }      # 约束 agent —— 安全属性
        tree:  { level: none }                      # 原行为：low + OI|CI 施加到工作区树
        scratch: { enabled: true, dir: '.dsh/sandbox' }
      acl:
        workspaceGrant: true                        # S-1-4-* 写授权
        deleteChildDeny:
          enabled: true
          sid: 'Everyone'
          flags: ['CI']
          scope: 'dsh-created'                      # 设为 `workspace` 即复刻今天的行为
        exclude: ['*.exe', '*.dll', '*.node']
      lifecycle:
        standing: false                             # 配置后默认按会话
        releaseCommand: true
```

上面**每一个默认值都精确保持今天的行为**，所以这是一个纯增量的配置面——不碰它的人什么都不会变。

## 为什么这不只是"图方便"的请求

这不仅仅是"让我放宽沙箱"。在最重要的那个维度上，**让用户能改这个设置，会让系统更安全**：

**给树打标，让工作区里的二进制变得更不受保护，而不是更受保护。**

- `.exe` 保持 `Medium` → 受限的 Low agent 进程受 `NO_WRITE_UP` 约束，**无法覆盖它**
- `.exe` 继承 `Low` → Low 的 agent 进程**可以**覆盖它
- 用户随后以 `Medium` 身份运行这个二进制——双击、`npm run dev`、安装器、CI

所以继承这件事，**授予了受限进程对"用户稍后要以提升身份运行的可执行文件"的写入能力**。这是一个由约束机制自己制造的新写入面。在这个维度上，把开关暴露出来是一个**加固**动作：`tree.level: none` + `token.level: low` 对这条威胁而言**严格优于现状**。

维护者的 README 已经承认了这个后果：

> 诊断保留完整性标签——它无法修复 Low 标签的可执行文件影响用户在 DSH 外启动程序的问题

**那是在记录"修不了"，不是在论证这个捆绑是唯一正确的姿态。** 而一个各项成本收益符号相反的捆绑包，正是配置面该出现的地方。

## 我不是在要什么

不是换个名字的 `danger-full-access`。那个模式连**文件防护**一起去掉了，而这一层我想留着：

| | 文件防护 | 进程约束 | 树被打标 |
| --- | --- | --- | --- |
| `danger-full-access` | ✗ | ✗ | ✗ |
| 今天的 `workspace-write` | ✓ | ✓ | ✓ 永久 |
| **我想要的** | **✓** | **✓** | **✗** |

我要的是中间那档姿态，而它现在不存在。

## 诉求

如果完整的策略配置现在体量太大，那么让这件事可操作的最低限度是：

1. **`dsh sandbox status` / `dsh sandbox release`** —— 能看见、能移除。单这一条就消掉了"不可恢复"这个属性。
2. **把 `integrity.token` 和 `integrity.tree` 拆开** —— 性价比最高的单个旋钮，因为它把安全属性和代价分开了。
3. **可执行文件不继承标签** —— 按上面的论证，这本来就该是默认值。
4. **拒绝卷根** —— 在写入之前（#11193）。

哪怕只做 1 + 2，也能把这件事从"打断我的开发循环而且我拦不住"变成"一个可以自己调的、有文档的取舍"。

愿意帮忙测试构建，也可以提供 P/Invoke 读完整性级别的脚本、`icacls` 前后对照输出、以及 `electron-builder` 的失败日志。
